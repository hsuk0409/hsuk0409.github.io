# AI 활용 경험

[이력서](/resume/)의 업무 경험이 "AI 에이전트로 무엇을 만들었는가"를 다룬다면, 이 페이지는 그보다 한 단계 앞선 이야기 — **AI 에이전트가 일하는 방식 자체를 어떻게 설계하고 검증했는가**를 다룹니다.

---

## 커스텀 스킬(Skill) 설계

### 마이그레이션 데이터 정합성 자동 진단 스킬 — 사내

레거시-신규 DB 마이그레이션 과정에서 물리 삭제 잔존, 식별키 불일치, 매핑 오염 등 같은 종류의 데이터 불일치가 반복적으로 발생했습니다(배경은 [이력서 — 학원 관리 프로그램 개발 및 서버 구축](/resume/#academy-program) 참고). 매번 개발자가 손수 여러 테이블을 SQL로 교차 조회하던 절차를, **5가지 진단 규칙 기반의 Read-Only 커스텀 스킬**로 표준화했습니다.

- 학생 ID·학원 코드 같은 최소 정보만 입력하면 에이전트가 안전한 조회 스크립트를 작성·실행하고 원인을 자동 판정
- `SELECT`만 허용하고 `UPDATE`/`DELETE`는 어떤 경우에도 수행하지 않도록 스킬 설계 단계에서 강제 — 자동화가 실수로 운영 데이터를 건드릴 위험을 원천 차단
- 진단 결과는 원인·비교 표·권장 보정 방안이 포함된 표준화된 보고서로 출력

## MCP 서버 직접 설계 및 성능 최적화 — 개인

당일 업무를 그때그때 정리해 기록하도록 스킬을 설정해, AI 에이전트에게 작업을 지시할 때마다 이 MCP로 로그를 남기게 했습니다. 퇴근 전에는 '업무 정리 스킬'로 그날 쌓인 로그를 모아 업무 보고 형태로 요약하는 과정까지 자동화했습니다. 이 업무 로그를 기록하는 MCP(Model Context Protocol) 서버를 Node.js로 직접 구현·운영하며 겪은 성능 문제를 스스로 진단하고 고쳤습니다.

- **문제**: 단일 로그 파일에 무한 누적하는 구조라, 오늘 로그 몇 줄을 확인하려 해도 매번 파일 전체(약 40,000 토큰)를 읽어 프롬프트에 주입 — 컨텍스트 낭비와 응답 지연 유발
- **해결**: KST(Asia/Seoul) 날짜 기준으로 `logs/YYYY-MM/work_log_YYYY-MM-DD.txt` 형태의 일별 자동 로테이션 구조로 재설계, 오늘 로그 파일만 핀포인트로 로드
- **효과**: 세션당 토큰 소모량 약 99% 감소(약 40,000 → 150 토큰). 도구의 스키마·인터페이스는 그대로 유지해 Claude Code, Gemini, Antigravity 등 여러 에이전트 런타임에서 설정 변경 없이 바로 재사용

## 멀티 에이전트 오케스트레이션

### 대량 계획서 병렬 감사 — 사내

프로젝트에 쌓인 계획서(`plans/*.md`) 91건 중 실제로 완료된 것과 방치된 것을 사람이 하나씩 읽고 확인하는 건 비현실적이었습니다. 8개 그룹으로 나눠 읽기 전용 서브에이전트에 병렬로 위임하고, 출력 형식(날짜·경로·제목·상태·근거)을 미리 표로 고정해 8개 에이전트의 결과를 기계적으로 이어 붙이는 방식으로 처리했습니다.

이 과정에서 확인한 것: **계획서의 체크리스트나 "완료" 문구는 실제 완료의 증거가 아닙니다.** 실제로는 이미 구현됐지만 체크리스트 갱신을 잊은 사례, 반대로 미착수로 보였지만 더 발전된 후속 계획서로 대체되어 사실상 완료인 사례가 둘 다 있었습니다 — 반드시 코드베이스와 직접 대조해야 한다는 걸 재확인했습니다.

### 멀티 에이전트 런타임 관리 — 사내

설계 명세서(SIP)와 Port-Adapter 가이드라인으로 아키텍처 정합성을 먼저 통제한 뒤, 여러 에이전트에 작업을 동시에 위임하는 방식으로 워크플로우를 확장했습니다. Herdr로 여러 에이전트의 CLI를 한 화면에서 관리하며 승인 대기 상태를 한눈에 파악해 즉시 대응했고, 화면이 꺼지거나 연결이 끊겨도 세션이 유지되어 장시간 작업이 끊기지 않도록 했습니다. (자세한 배경은 [이력서 — 학원 관리 프로그램 개발 및 서버 구축](/resume/#academy-program) 참고)
